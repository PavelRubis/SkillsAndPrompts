# Дневник (Notion Diary)

Скилл для ведения личного дневника в Notion. В течение дня Паша пишет свои мысли, а в конце дня создаётся страница в Notion Data Source со всеми мыслями и саммари дня.

## Notion API

- **Версия API:** `2026-03-11` (всегда в заголовке `Notion-Version`)
- **Токен:** читать из `state/.notion_token`, устанавливать `export NOTION_API_TOKEN=*** ~/.openclaw/workspace/state/.notion_token)`. Никогда не выводить токен в ответах/логах.
- **Data Source ID:** хранится в `state/diary.json`, поле `data_source_id`. Дневник — это **датасорс** (data source), не обычная база данных.
- При создании страницы: `parent: { data_source_id: "..." }`, а НЕ `database_id`. С `database_id` возвращается 404.
- **Токен может ТОЛЬКО создавать страницы.** Не может читать или обновлять существующие.

## Буфер = JSON payload cron-задачи

Данные дневника хранятся в `payload.message` задачи `diary-auto-create` в формате JSON. Никаких файлов-буферов.

Формат:
```json
{
  "date": "YYYY-MM-DD",
  "entries": [
    {"time": "HH:MM", "text": "текст записи"}
  ]
}
```

Пример буфера с двумя записями:
```json
{
  "date": "2026-07-04",
  "entries": [
    {"time": "10:15", "text": "Утром пробежка, чувствую себя отлично"},
    {"time": "15:30", "text": "Дописал тот баг — оказывается, проблема была в кэше"}
  ]
}
```

Пример пустого буфера:
```json
{
  "date": "2026-07-04",
  "entries": []
}
```

## Добавление записи в дневник (основная сессия)

Когда Паша говорит «добавь в дневник: [текст]»:

1. Выполни `cron get` для задачи `diary-auto-create` — получи `payload.message`
2. Распарси JSON из `payload.message`
3. Если `date` не равен сегодняшней дате (новый день) — сбрось: `date = сегодня`, `entries = []`
4. Добавь запись: `{"time": "HH:MM", "text": "текст Паши"}`, время MSK
5. Собери новый JSON и выполни `cron update` задачи `diary-auto-create`
6. **Обнови также payload задачи `diary-reminder`** (см. секцию «Напоминалка»)

## Создание заметки в Notion

Два способа:
1. **По прямой команде** Паши «создай заметку дневника» — немедленно (основная сессия)
2. **Автоматически в 22:00 MSK (19:00 UTC)** — через cron `diary-auto-create` (изолированная сессия)

### Прямая команда (основная сессия)

1. Выполни `cron get` для `diary-auto-create` → распарси JSON из `payload.message`
2. Если `entries` пуст — сообщи Паше «Нечего создавать», выходи
3. Если записи есть:
   - Прочитай `state/.notion_token` и `state/diary.json`
   - Сформируй контент заметки (см. «Формат контента» ниже)
   - Создай страницу через Notion API (см. «Создание страницы (curl)» ниже)
   - После успеха — сообщи Паше (со ссылкой)
   - Очисти payload: `cron update` с `{"date": "сегодня", "entries": []}`
   - Обнови `diary-reminder`: статус «пуст»

### Автосоздание через cron (изолированная сессия, 22:00 MSK)

Агент получает данные в `payload.message`. Процесс:

1. Распарси JSON из `payload.message`
2. Если `entries` пуст — ответь `NO_REPLY`
3. Если записи есть:
   - Прочитай `state/.notion_token` и `state/diary.json`
   - Сформируй контент заметки (см. «Формат контента» ниже)
   - Создай страницу через Notion API (см. «Создание страницы (curl)» ниже)
   - После успеха — сообщи результат
   - **НЕ делай `cron update`** — ты в изолированной сессии

### Правила

- На каждый день — одна заметка
- Формат названия: `Дневник — YYYY-MM-DD`
- Тип1 = Дневник

### Формат контента

Для каждой записи: блок `heading_3` с **HH:MM** (время MSK), затем блок(и) `paragraph` с полным текстом.

После всех записей — разделительный блок `divider`, затем `heading_3` «Саммари дня», затем `paragraph` с кратким summary (2-5 предложений).

### Создание страницы (curl)

```bash
export NOTION_API_TOKEN="$(cat ~/.openclaw/workspace/state/.notion_token)"
export NOTION_API_VERSION=2026-03-11
DS_ID="$(jq -r '.data_source_id' ~/.openclaw/workspace/state/diary.json)"

curl -sS "https://api.notion.com/v1/pages" \
  -H "Authorization: Bearer $NOTION_API_TOKEN" \
  -H "Notion-Version: 2026-03-11" \
  -H "Content-Type: application/json" \
  -d '{
    "parent": {"data_source_id": "'"$DS_ID"'"},
    "properties": {
      "Название": {"title": [{"text": {"content": "Дневник — YYYY-MM-DD"}}]},
      "Тип1": {"select": {"name": "Дневник"}}
    },
    "children": [...]
  }'
```

Ссылка на созданную страницу:
```bash
PAGE_ID="из ответа API"
URL_ID="${PAGE_ID//-/}"
echo "https://notion.so/$URL_ID"
```

## Напоминалка (20:00 MSK, изолированная сессия)

Payload задачи `diary-reminder` содержит статус буфера. Основная сессия обновляет его при каждом изменении.

Формат `payload.message` для `diary-reminder`:

Если буфер не пуст (X записей):
```
Напоминалка дневника. Буфер НЕ ПУСТ (X записей). Ответь: NO_REPLY
```

Если буфер пуст:
```
Напоминалка дневника. Буфер ПУСТ. Отправь Паше сообщение: «Сегодня ещё ничего не добавлено в дневник. Может, есть что записать?»
```

Агент в 20:00 MSK:
1. Прочитай `payload.message`
2. Если «НЕ ПУСТ» — ответь `NO_REPLY`
3. Если «ПУСТ» — отправь напоминание Паше
4. **ТОЛЬКО про дневник.** Никаких других задач.

## Cron-задачи

Две cron-задачи, обе в `Europe/Moscow`, обе `sessionTarget: isolated`, обе `payload.kind: agentTurn`:

1. **diary-reminder** — `0 20 * * *` — проверка статуса (через payload), напоминание если пуст
2. **diary-auto-create** — `0 22 * * *` — автосоздание заметки (записи из JSON payload)

Payload'ы обеих задач обновляются основной сессией при каждом добавлении записи или создании заметки.
