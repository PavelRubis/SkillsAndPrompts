# Дневник (Notion Diary)

Скилл для ведения личного дневника в Notion. В течение дня Паша пишет свои мысли, а в конце дня создаётся страница в Notion Data Source со всеми мыслями и саммари дня.

## Notion API

- **Версия API:** `2026-03-11` (всегда в заголовке `Notion-Version`)
- **Токен:** читать из `state/.notion_token`, устанавливать `export NOTION_API_TOKEN=*** state/.notion_token)`. Никогда не выводить токен в ответах/логах.
- **Data Source ID:** хранится в `state/diary.json`, поле `data_source_id`. Дневник — это **датасорс** (data source), не обычная база данных.
- При создании страницы: `parent: { data_source_id: "..." }`, а НЕ `database_id`. С `database_id` возвращается 404.
- **Токен может ТОЛЬКО создавать страницы.** Не может читать или обновлять существующие.

## Буфер

Буфер — временное хранилище мыслей за день. Все записи накапливаются в нём до момента создания итоговой заметки в Notion.

Файл: `state/diary_buffer.json`

Формат:
```json
{
  "date": "YYYY-MM-DD",
  "entries": [
    {
      "time": "HH:MM",
      "text": "текст записи"
    }
  ],
  "noteCreated": false
}
```

### Добавление записи в буфер

Когда Паша говорит «добавь в дневник: [текст]»:
1. Прочитай `state/diary_buffer.json`
2. Добавь запись в `entries` с меткой времени HH:MM MSK
3. Сохрани обновлённый буфер

### Сброс буфера — КРИТИЧЕСКИ ВАЖНО

После успешного создания заметки в Notion (или если буфер пуст при автосоздании) **ОБЯЗАТЕЛЬНО** сбрось буфер:

1. Запиши в `state/diary_buffer.json`:
   - `date` = завтрашняя дата (YYYY-MM-DD)
   - `entries = []`
   - `noteCreated = false`
2. **СРАЗУ после записи — прочитай файл обратно и проверь**, что `date` действительно равен завтрашней дате.
3. Если `date` НЕ обновился (всё ещё старая дата) — **запиши файл ещё раз** и снова проверь.
4. Повторяй до 3 попыток. Если после 3 попыток `date` так и не обновился — сообщи об ошибке Паше.

Пример сброшенного буфера (если сегодня 2026-07-01, а заметка создана):
```json
{
  "date": "2026-07-02",
  "entries": [],
  "noteCreated": false
}
```

**Никогда не возвращай `NO_REPLY` до того, как буфер реально сброшен и проверен.**

## Создание заметки в Notion

Происходит одним из двух способов:
1. **По прямой команде** Паши «создай заметку дневника» — немедленно
2. **Автоматически в 22:00 MSK (19:00 UTC)**, если команда не поступала

### Процесс создания

1. Прочитай `state/diary_buffer.json`
2. Если `noteCreated === true` ИЛИ `entries` пуст:
   - Выполни **сброс буфера** (см. секцию «Сброс буфера — КРИТИЧЕСКИ ВАЖНО») с обязательной проверкой
   - Только после подтверждённого сброса ответь `NO_REPLY`
3. Если `noteCreated === false` И `entries` не пуст:
   - Прочитай `state/diary.json` — получи `data_source_id`
   - Прочитай `state/.notion_token` — получи API-токен
   - Сформируй контент заметки:
     - Для каждой записи: **HH:MM** (время MSK) + полный текст
     - Разделитель `---`
     - Краткое summary дня (2-5 предложений) на основе всех записей
   - Создай страницу в Notion через API:
     - `properties`: «Название» = `Дневник — YYYY-MM-DD`, «Тип1» = «Дневник»
     - `parent`: `{ data_source_id: "..." }`
   - После успешного создания — сообщи Паше (со ссылкой если доступна)
   - **СРАЗУ** выполни сброс буфера с проверкой (см. секцию «Сброс буфера — КРИТИЧЕСКИ ВАЖНО»)

### Правила

- На каждый день — одна заметка
- Формат названия: `Дневник — YYYY-MM-DD`
- Тип1 = Дневник

## Напоминалка (20:00 MSK)

В 20:00 MSK проверяю буфер:
- Если `entries` пуст — одно сообщение: «Сегодня ещё ничего не добавлено в дневник. Может, есть что записать?»
- Если `entries` не пуст — ничего не делаю, `NO_REPLY`
- **ТОЛЬКО про дневник.** Никаких других задач, никаких посторонних напоминаний.

## Cron-задачи

Две cron-задачи, обе в `Europe/Moscow`:

1. `diary-reminder` — `0 20 * * *` — проверка буфера, напоминание если пуст
2. `diary-auto-create` — `0 22 * * *` — автосоздание заметки
