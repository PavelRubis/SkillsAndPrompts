# Дневник (Notion Diary)

Скилл для ведения личного дневника в Notion. В течение дня Паша пишет свои мысли, а в конце дня создаётся страница в Notion Data Source со всеми мыслями и саммари дня.

## Пути (Hermes)

- Каталог состояния: `~/.hermes/state/`
- Токен Notion: `~/.hermes/state/.notion_token`
- Метаданные дневника: `~/.hermes/state/diary.json` (поле `data_source_id`)
- Буфер записей: `~/.hermes/state/diary_buffer.json`

## Notion API

- **Версия API:** `2026-03-11` (всегда в заголовке `Notion-Version`)
- **Токен:** читать из `~/.hermes/state/.notion_token` → `export NOTION_API_TOKEN="$(cat ~/.hermes/state/.notion_token)"`. Никогда не выводить токен в ответах/логах.
- **Data Source ID:** хранится в `~/.hermes/state/diary.json`, поле `data_source_id`. Дневник — это **датасорс** (data source), не обычная база данных.
- При создании страницы: `parent: { data_source_id: "..." }`, а НЕ `database_id`. С `database_id` возвращается 404.
- **Токен может ТОЛЬКО создавать страницы.** Не может читать или обновлять существующие.

## Буфер = файл `~/.hermes/state/diary_buffer.json`

Записи дневника хранятся в JSON-файле буфера. (В OpenClaw-версии буфером был `payload.message` cron-задачи; в Hermes у cron-задачи нет обновляемого payload, поэтому источник истины — файл.)

Формат:
```json
{
  "date": "YYYY-MM-DD",
  "entries": [
    {"time": "HH:MM", "text": "текст записи"}
  ]
}
```

Пример буфера с двумя записями:
```json
{
  "date": "2026-07-04",
  "entries": [
    {"time": "10:15", "text": "Утром пробежка, чувствую себя отлично"},
    {"time": "15:30", "text": "Дописал тот баг — оказывается, проблема была в кэше"}
  ]
}
```

Пример пустого буфера:
```json
{
  "date": "2026-07-04",
  "entries": []
}
```

Дата/время по MSK: `TZ=Europe/Moscow date +%F` / `TZ=Europe/Moscow date +%H:%M`.

## Добавление записи в дневник (основная сессия)

Когда Паша говорит «добавь в дневник: [текст]»:

1. Прочитай `~/.hermes/state/diary_buffer.json` (файла нет — считай буфер пустым)
2. Распарси JSON
3. Если `date` не равен сегодняшней дате (MSK) — **сбрось буфер на сегодня**: `date = сегодня (MSK)`, `entries = []`. Это покрывает кейс, когда вчерашние записи зависли.
4. Добавь запись в entries: `{"time": "HH:MM", "text": "текст Паши"}`, время MSK.

   **ВАЖНО — дословность:** текст записи сохраняется **дословно** — именно так, как сказал Паша. Никакого переформулирования, исправления грамматики, саммаризации или изменения смысла. Это прямая транскрибация/цитата, а не пересказ.
5. Запиши JSON обратно в `~/.hermes/state/diary_buffer.json` (атомарно: временный файл рядом + `mv`).

Больше ничего обновлять не нужно: cron-задачи читают буфер напрямую.

## Создание заметки в Notion

Два способа:
1. **По прямой команде** Паши «создай заметку дневника» — немедленно (основная сессия)
2. **Автоматически в 22:00 MSK (19:00 UTC)** — cron-задача `diary-auto-create` (свежая сессия)

### Прямая команда (основная сессия)

1. Прочитай `~/.hermes/state/diary_buffer.json`
2. Если `date` ≠ сегодня (MSK) или `entries` пуст — сообщи Паше «Нечего создавать» и выходи
3. Если записи есть:
   - Прочитай `~/.hermes/state/.notion_token` и `~/.hermes/state/diary.json`
   - Сформируй контент заметки (см. «Формат контента»)
   - Создай страницу через Notion API (см. «Создание страницы (curl)»)
   - После успеха — сообщи Паше со ссылкой
   - Очисти буфер: запиши `{"date": "<сегодня MSK>", "entries": []}`

### Автосоздание через cron (22:00 MSK)

Задача `diary-auto-create` запускается в свежей сессии без контекста чата, поэтому её prompt самодостаточен: он велит прочитать навык и буфер.

1. **Прочитай навык** через `skill_view(name="diary")`, секцию «Автосоздание через cron»
2. Прочитай `~/.hermes/state/diary_buffer.json`
3. **Проверь дату.** Если `date` не равен сегодняшней (MSK) — это вчерашние записи, которые зависли. Ответь одной строкой `Дневник: записей нет, заметка не создана.` и выходи (основная сессия сбросит буфер при следующем касании).
4. Если `entries` пуст — ответь той же строкой и выходи
5. Если записи есть и дата сегодня (MSK):
   - Прочитай `~/.hermes/state/.notion_token` и `~/.hermes/state/diary.json`
   - Сформируй контент заметки (см. «Формат контента»)
   - Создай страницу через Notion API
   - После успеха — ответь ссылкой на созданную страницу
   - **Буфер не очищай** — cron-сессии не перезаписывают состояние; очистку делает основная сессия

### Правила

- На каждый день — одна заметка
- Формат названия: `Дневник — YYYY-MM-DD`
- Тип1 = `Дневник`

### Формат контента

Для каждой записи: блок `heading_3` с **HH:MM** (время MSK), затем блок(и) `paragraph` с полным текстом.

**Текст каждой записи вставляется дословно** — так, как он сохранён в буфере. Никакого переформулирования при создании заметки.

После всех записей — `divider`, затем `heading_3` «Саммари дня», затем `paragraph` с кратким саммари (2–5 предложений).

### Создание страницы (curl)

```bash
export NOTION_API_TOKEN="$(cat ~/.hermes/state/.notion_token)"
DS_ID="$(jq -r '.data_source_id' ~/.hermes/state/diary.json)"

curl -sS "https://api.notion.com/v1/pages" \
  -H "Authorization: Bearer $NOTION_API_TOKEN" \
  -H "Notion-Version: 2026-03-11" \
  -H "Content-Type: application/json" \
  -d '{
    "parent": {"data_source_id": "'"$DS_ID"'"},
    "properties": {
      "Название": {"title": [{"text": {"content": "Дневник — YYYY-MM-DD"}}]},
      "Тип1": {"select": {"name": "Дневник"}}
    },
    "children": [...]
  }'
```

Ссылка на созданную страницу:
```bash
PAGE_ID="из ответа API"
echo "https://notion.so/${PAGE_ID//-/}"
```

## Напоминалка (20:00 MSK)

Реализована **скриптом без LLM**: cron-задача `diary-reminder` с `no_agent: true` и `script: diary_reminder.py`. Скрипт печатает напоминание только когда оно нужно; пустой stdout = Hermes ничего не отправляет (нет спама в дни, когда запись уже есть).

Скрипт лежит в репозитории скиллов: `skills/diary/scripts/diary_reminder.py`. Устанавливается копированием в `~/.hermes/scripts/diary_reminder.py` — cron разрешает относительные пути `script` именно от `~/.hermes/scripts/`.

Логика:
1. Читает `~/.hermes/state/diary_buffer.json`
2. Если файла нет, JSON битый, `date` ≠ сегодня (MSK) или `entries` пуст — печатает **ровно одну строку**:
   > Сегодня ещё ничего не добавлено в дневник. Может, есть что записать?
3. Иначе — не печатает ничего

Если напоминание когда-то придётся отправить вручную: **никаких** упоминаний старых записей, их количества и дат — только фраза выше.

## Первый вход нового дня (основная сессия)

При старте сессии или первом касании дневника за день основная сессия **проверяет актуальность буфера**:

1. Прочитай `~/.hermes/state/diary_buffer.json`
2. Если `date` ≠ сегодня (MSK) — вчерашние записи зависли. Сбрось буфер: `{"date": "<сегодня MSK>", "entries": []}`
3. Если `date` = сегодня — ничего не делать

Это гарантирует, что старые записи не висят в буфере бесконечно.

## Cron-задачи (Hermes)

Обе задачи создаются тулом `cronjob_manage`, таймзона `Europe/Moscow`, доставка в чат Паши (`deliver` по умолчанию = чат создания).

1. **diary-reminder** — `schedule: "0 20 * * *"`, `no_agent: true`, `script: "diary_reminder.py"`, `timezone: "Europe/Moscow"`.
   LLM не вызывается, stdout скрипта уходит Паше как есть.
2. **diary-auto-create** — `schedule: "0 22 * * *"`, `timezone: "Europe/Moscow"`, обычная агентская задача.
   `prompt`: «Прочитай навык `diary` (skill_view) и `~/.hermes/state/diary_buffer.json`. Действуй по секции «Автосоздание через cron». Если записей за сегодня нет — ответь одной строкой и страницу не создавай.»
   `skills: ["diary"]`, `enabled_toolsets: ["terminal"]` (Notion дёргается curl'ом).

Проверить/поправить: `cronjob_manage(action="list")` → `action="update"` с нужным `job_id`.

⚠️ Не хранить состояние в prompt cron-задачи: в Hermes его нельзя обновлять как `payload.message` в OpenClaw. Источник истины — файл буфера.
