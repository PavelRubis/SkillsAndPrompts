# Yandex Reviews Analyzer

Анализирует отзывы заведения на Яндекс.Картах: собирает до 100 самых новых через тул `yandex_maps_place_reviews`, фильтрует негативные, категоризирует по степени критичности (средняя/высокая/критичная).

## Триггер

Пользователь кидает ссылку на заведение на `yandex.ru/maps/org/...` или `yandex.com/maps/org/...`.

## Процесс

### 1. Сбор отзывов через тул

Вызвать тул `yandex_maps_place_reviews` с параметрами:
- `url` — ссылка на страницу отзывов заведения
- `count` — **обязательно** 100 (если пользователь явно не указал другое число)

Тул возвращает JSON с полями:
- `reviews[]` — массив отзывов, каждый с полями `date` (ISO-дата), `text` (текст отзыва) и `url` (ссылка на конкретный отзыв, может отсутствовать)
- `stats` — метаданные сбора (попытки, капчи, скроллы)

Отзывы уже отсортированы по новизне (новые первыми). Никакой браузерной автоматизации не требуется.

**Важно:** тул возвращает только `date`, `text` и `url`. Рейтинг (звёзды) и имя автора **недоступны**.

### 2. Фильтрация негативных

Поскольку рейтинг недоступен, негативность определяется **только по тексту отзыва**:

**Явно негативный отзыв** (текст содержит):
- Прямые жалобы: «ужасно», «отвратительно», «разочарование», «не советую», «никому не рекомендую», «кошмар»
- Претензии к качеству: «невкусная еда», «невкусно», «никакая кухня», «еда ужасная», «отравился», «испорченный»
- Проблемы с сервисом: «хамство», «хамский», «нахамил», «обсчитали», «обман», «мошенничество»
- Санитарные проблемы: «грязно», «антисанитария», «насекомые», «тараканы», «волосы», «стекло», «пластик», «осколки»
- Организационные провалы: «долгое ожидание», «ждали час», «ждали 30 минут», «не дождались», «ушли голодные»
- Финансовые претензии: «оверпрайс», «не стоит своих денег», «дорого», «скрытые платежи», «сервисный сбор»

**Нейтральный/позитивный отзыв** (игнорируется):
- Текст преимущественно хвалебный: «понравилось», «вкусно», «рекомендую», «супер», «отлично», «восторг», «классно»
- Даже если есть мелкое замечание среди похвалы — считать позитивным, если позитив явно перевешивает
- Нейтральные: «один раз сходить можно», «ничего особенного», «интересно, но еда не очень»

**Пограничные случаи:**
- Если отзыв содержит и позитив, и негатив в равной мере — классифицировать по преобладающему тону
- Если сомнение — относить к негативным (лучше перестраховаться)

### 3. Категоризация по критичности

| Уровень | Критерии |
|---------|----------|
| 🔴 **Критичная** | Антисанитария, отравление, насекомые/грызуны, инородные предметы в еде (стекло, пластик, осколки), хамство персонала, обсчёт/мошенничество, скрытые платежи, нарушение закона, угрозы безопасности |
| 🟠 **Высокая** | Плохое качество еды/напитков, долгое ожидание (30+ минут), грязно, несоответствие описанию/цене, халатность персонала (потеря брони и т.п.), несколько проблем в одном отзыве, организация на нуле |
| 🟡 **Средняя** | Мелкие неудобства, «могло быть лучше», нестабильность качества, не понравился интерьер/музыка, одноразовая мелкая проблема, субъективные претензии, «оверпрайс», «не стоит своих денег» |

Категоризация — на основе текста, с учётом контекста и серьёзности описания.

### 4. Формат вывода

Для каждого негативного отзыва: **дата как markdown-ссылка на отзыв (используя поле `url`) + краткое описание (1 предложение)**. Если у отзыва нет поля `url` — вывести дату без ссылки. Полные тексты отзывов **не выводятся**.

Формат даты: `YYYY-MM-DD` (из ISO-даты тула, приведённой к MSK). Пример: `[2026-08-01](url_отзыва)`.

```
🔍 Анализ отзывов: [Название заведения]
Ссылка: [URL страницы отзывов]

Проанализировано: N отзывов (самые новые)
Негативных: M

🔴 КРИТИЧНЫЕ (K):
1. [YYYY-MM-DD](url) — [краткое описание сути претензии]

🟠 ВЫСОКИЕ (L):
...

🟡 СРЕДНИЕ (P):
...
```

- Название заведения — извлечь из URL или из контекста страницы.
- Дата каждого отзыва оформляется как markdown-ссылка в формате `[YYYY-MM-DD](url_отзыва)`. Если `url` отсутствует — просто дата текстом.
- Краткое описание — 1 предложение, суть претензии (например: «Стекло в хачапури, персонал отрицал проблему»).
- Поля «Автор» и «★Рейтинг» исключены, так как тул их не возвращает.
- **Полные тексты отзывов не включаются в вывод.**

Если негативных нет: «Среди N последних отзывов негативных не найдено 🔥»

## Зависимости

- Плагин `@sharleysoft/openclaw-yandex-maps-places-review` (должен быть установлен и включён в `plugins.entries`)
- Тул `yandex_maps_place_reviews` должен быть разрешён в `tools.alsoAllow`

## Notes

- Тул `yandex_maps_place_reviews` использует Playwright под капотом и сам обрабатывает скролл, сортировку и извлечение данных.
- Капчи обрабатываются тулом автоматически (счётчик `captchaReloads` в `stats`).
- Если у заведения < 100 отзывов — тул вернёт все доступные.
- Поскольку рейтинг недоступен, фильтрация негативных полагается только на анализ текста — это менее точно, чем при наличии звёзд, но покрывает основные сценарии.
- Если в будущем тул начнёт возвращать рейтинг — обновить секцию «Фильтрация негативных» для использования звёзд.
- Тул возвращает `url` для каждого отзыва (ссылка на конкретный отзыв на Яндекс.Картах) — использовать для markdown-ссылок в датах. Но если `url` отсутствует — выводить дату без ссылки.
